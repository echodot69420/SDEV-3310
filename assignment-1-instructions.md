## Purpose

Build the first working version of a Library Management System API. This milestone asks you to apply the same REST, Pydantic, router, HTTP-status, and OpenAPI practices demonstrated in the Project and Task Management API while making the implementation decisions yourself for Books and Members.

> **Scope boundary:** Database persistence is not required in Assignment 1 because the assignment is due before the persistence module. Use simple application-memory collections. Assignment 2 will replace this temporary state with SQLAlchemy and a relational database.

## Learning Outcomes

- Design resource-oriented routes using nouns, plural paths, and standard HTTP methods.
- Create separate Pydantic request and response schemas with meaningful validation.
- Implement complete CRUD behavior for two related resources.
- Enforce a one-to-many Member-to-Book relationship and support retrieving the Books associated with a Member.
- Return status codes and response bodies that accurately describe each outcome.
- Publish a usable OpenAPI contract and explain how to run the project.

## Required Resources

| Field | Type | Requirement |
| --- | --- | --- |
| `id` | Integer | Generated by the application; response only |

### Member

| Field | Type | Requirement |
| --- | --- | --- |
| `id` | Integer | Generated by the application; response only |

> **Relationship model:** For this course milestone, each Book record represents one library item borrowed by exactly one Member. A Member may have many Books. This intentionally mirrors the demonstrated Project-to-Tasks relationship: `Book.member_id` is the child-side reference, the referenced Member must exist, and clients must be able to retrieve the Books associated with a Member.

## Required API Operations

The assignment defines the behavior the API must support, but it does not prescribe endpoint paths or an endpoint count. Use the lecture notes and the Project and Task Management API as references, then design the resource paths, HTTP methods, request bodies, response bodies, and status codes using the REST conventions demonstrated in class.

### Books

- Create a new Book.
- Retrieve all Books.
- Retrieve one Book by its identifier.
- Update an existing Book.
- Delete an existing Book.

### Members

- Create a new Member.
- Retrieve all Members.
- Retrieve one Member by its identifier.
- Update an existing Member.
- Delete an existing Member.
- Retrieve the Books associated with a Member.

## Business Requirements

- Library staff must be able to create, retrieve, update, and delete Book and Member records.
- Each Book must be associated with exactly one existing Member, and a Member may have multiple Books.
- Library staff must be able to retrieve the Books associated with a Member.
- Each ISBN, Member email address, and membership ID must be unique.
- The system must reject missing, incomplete, or invalid Book and Member information.
- The system must clearly indicate when a requested Book, Member, or related record does not exist.
- A Member who still has associated Books cannot be deleted. Those Books must first be deleted or reassigned.
